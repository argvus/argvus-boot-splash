# Архитектура темы

Как устроена тема Plymouth: дескриптор, набор ресурсов и что делает
`argvus.script`, по разделам.

Для упаковки и релизов см. [packaging](/docs/argvus-boot-splash/developer-guide/packaging/)] и
[CI and releases](/docs/argvus-boot-splash/developer-guide/ci-releases/)]. Для использования см.
[руководство пользователя](/docs/argvus-boot-splash/)].

## Дескриптор

Темы Plymouth представляют собой декларативные дескрипторы, интерпретируемые скриптовым
движком Plymouth. Состоят из двух частей:

`src/usr/share/plymouth/themes/argvus/argvus.plymouth`:

```ini
[Plymouth Theme]
Name=Argvus
Description=Argvus boot splash theme
ModuleName=script

[script]
ImageDir=/usr/share/plymouth/themes/argvus
ScriptFile=/usr/share/plymouth/themes/argvus/argvus.script
```
Заметки:

- `ModuleName=script` выбирает встроенный интерпретатор скриптов Plymouth. Компилируемого модуля нет; `ImageDir` и `ScriptFile` должны быть **абсолютными путями**, так как initramfs имеет другую рабочую директорию, чем ваша сессия.
- Имя файла является именем темы: `argvus.plymouth` ⇒ тема `argvus`, которую выбирает `plymouth-set-default-theme argvus`.
- `argvus.script` — единственный файл с кодом. Он выполняется внутри встроенной виртуальной машины Plymouth (связана с `plymouthd` и initramfs). Следствия: нет работы с файлами, нет потоков, нет внешних процессов, нет чисел с плавающей запятой, `MathInt` — единственная арифметика, а язык — это небольшой диалект, похожий на C (массивы — это объекты с ключами, объекты `Sprite()` должны быть созданы перед использованием).

## Модель рендеринга

- Один сплошной фон (`Window.SetBackgroundTopColor` / `SetBackgroundBottomColor`).  
- **Спрайты** — единственные примитивы для рисования. Каждый `Sprite()` имеет изображение, позицию `(x, y)`, **z-порядок** и непрозрачность в `[0, 1]`. Позже `SetPosition` вызывает win; граф сцены отсутствует.  
- Прогресс отображается повторным `ImageScale` изображения каждый кадр и вызовом `SetImage` на спрайте — нет обрезки или примитива для частичного рисования.  
- Plymouth сообщает о состоянии через обратные вызовы, которые регистрирует скрипт: `PlymouthSetBootProgressFunction`, `PlymouthSetDisplayPasswordFunction`, `PlymouthSetDisplayNormalFunction`, `PlymouthSetRefreshFunction`.  
- `Plymouth.SetRefreshRate(20)` заставляет обратный вызов обновления работать с 20 кадрами в секунду; единственная анимация с таймером темы (появление) зависит от этого.

## Инвентарь ресурсов

Все ресурсы находятся в `src/usr/share/plymouth/themes/argvus/`.

| Файл | Размер | Формат | Роль | Используется `argvus.script` |
| --- | --- | --- | --- | --- |
| `argvus.plymouth` | — | INI | дескриптор темы | загружен `plymouthd` |
| `argvus.script` | — | Скрипт Plymouth | логика темы | да |
| `argvus-logo.png` | 256x256 | RGBA 8-бит | основной логотип | да (`logo.base_scale = 0.72`) |
| `argvus-text.png` | 400x53 | RGBA 8-бит | надпись `ARGVUS` | да (`text.scale = 0.80`) |
| `progress-bar.png` | 400x4 | 1-битная палитра | заполненная полоса | да |
| `progress-bar-track.png` | 400x4 | 1-битная палитра | незаполненная дорожка | да |
| `entry-box.png` | 400x48 | RGB 16-бит | поле ввода пароля | да |
| `bullet.png` | 12x12 | 4-битная палитра | один скрытый символ | да |
| `entry-line.png` | 300x2 | 1-битная палитра | правило ввода/подчеркивание | нет (см. [известные пропуски](/docs/argvus-boot-splash/developer-guide/workflow/#known-gaps)) |
| `logo-glow.png` | 260x300 | 8-битная палитра | эффект свечения логотипа | нет (см. [известные пропуски](/docs/argvus-boot-splash/developer-guide/workflow/#known-gaps)) |
| `argvus-uki-splash.bmp` | 400x400 | BMP 32-бит | UKI / systemd-boot splash | нет (используется загрузчиком) |

Ширина изображения используется как единица компоновки: эталоном ширины является логотип
(400 пикселей при масштабе 1.0), а дорожка прогресса, индикатор прогресса и поле для ввода пароля
все выводятся из него, поэтому композиция остаётся согласованной, если
логотип будет повторно экспортирован.

`arch_check_splash_payload()` в `packaging/arch/common/functions.sh` требует, чтобы
**все** перечисленные выше файлы существовали; добавление ресурса означает добавление его в этот список. См.
[packaging](/docs/argvus-boot-splash/developer-guide/packaging/#shared-functions)].

## Обзор скрипта

`src/usr/share/plymouth/themes/argvus/argvus.script`, сверху вниз.

### 1. Фон

```js
Window.SetBackgroundTopColor(0.0667, 0.0745, 0.0863);
Window.SetBackgroundBottomColor(0.0667, 0.0745, 0.0863);
```
Одинаковое значение сверху и снизу ⇒ сплошная заливка, без градиента. Компоненты — это 8-битные каналы `#111316`, делённые на 255.

### 2. Ресурсы и масштабирование

Каждое изображение загружается через `Image("name")`, который разрешается относительно `ImageDir`. Масштабирование является явным:

```js
logo.base_scale = 0.72;
logo.base_width = MathInt(logo.original_image.GetWidth() * logo.base_scale);
logo.frame[logo.base_width] = ImageScale(logo.original_image, logo.base_width,
                                         logo.base_height);
logo.image = logo.frame[logo.base_width];
```
Кэш `logo.frame[...]` сделан намеренно: `ImageScale` на каждом кадре создавал бы новое изображение; логотип масштабируется один раз и кэшируется по целевой ширине, так что при изменении размера нужен только новый элемент в кэше.

Слово-логотип следует той же идее на `text.scale = 0.80`, но масштабируется один раз inline. Элементы трека прогресса и полосы затем масштабируются до `text.image.GetWidth()` — то есть полоса всегда соответствует ширине словоязыка, независимо от реального размера словоязыка в пикселях.

### 3. Макет

Каждый элемент выровнен по горизонтальной оси окна:

```js
logo.x = Window.GetX() + Window.GetWidth() / 2 - logo.image.GetWidth() / 2;
logo.y = Window.GetY() + Window.GetHeight() / 2 - logo.image.GetHeight() / 2 - 35;
```
Обратите внимание на `- 35`: стек расположен по центру всей композиции (логотип + словообраз + трек), а не только логотипа, поэтому блок находится немного выше вертикального центра экрана. Вертикальное размещение затем определяется относительно предыдущего элемента (`text.y = logo.y + logo.image.GetHeight() + 16`, `progress_track.y = text.y + text.image.GetHeight() + 28`, ...), что означает, что композиция масштабируется как единое целое с изменением разрешения.

Z-порядок, используемый здесь:

| Z | Спрайт |
| --- | --- |
| 100 | логотип, словообраз, трек прогресса |
| 101 | индикатор прогресса (над треком) |
| 200 | поле ввода пароля |
| 201 | текст запроса пароля |
| 202 | точки пароля |

### 4. Прогресс загрузки

```js
fun progress_callback(duration, progress)
{
    width = MathInt(progress_bar.original_image.GetWidth() * progress);
    if (width < 1) width = 1;
    if (width > progress_bar.original_image.GetWidth())
        width = progress_bar.original_image.GetWidth();
    progress_bar.image = ImageScale(progress_bar.original_image, width,
                                     progress_bar.original_image.GetHeight());
    progress_bar.sprite.SetImage(progress_bar.image);
}
```
Зарегистрировано с `PlymouthSetBootProgressFunction(progress_callback)`. Захват имеет значение: изображение с нулевой шириной недействительно в некоторых версиях Plymouth, поэтому панель никогда полностью не исчезает, и ход выполнения никогда не превышает ширину трека. Позиция спрайта фиксирована; изменяется только ширина изображения — не используются операции заполнения или обрезки.

### 5. Диалоговое окно пароля

`display_password_callback(prompt, bullets)`:

1. Затемняет заставку: `logo.opacity = 0.15` и логотип на `0.15`, в то время как дорожка и полоса остаются на `1.0`.
2. Отображает подсказку с `Image.Text(prompt, 0.72, 0.77, 0.81)` — единственное изображение, созданное во время выполнения темы. Его позиция известна только здесь, потому что она зависит от высоты текста.
3. Размещает поле ввода под подсказкой: password.entry.y = password.prompt.y + password.prompt.image.GetHeight() + 14. При загрузке `password.entry.y` равно `0` с комментарием, что реальная позиция ожидает подсказки.
4. Рисует маркеры с помощью цикла создания или повторного использования:

   ```js
   for (index = 0; password.bullet[index] || index < bullets; index++)
   {
       if (!password.bullet[index]) { /* create sprite + image */ }
       /* ...position at entry.x + 16 + index * bullet.width ... */
       if (index < bullets) sprite.SetOpacity(1); else sprite.SetOpacity(0);
   }
   ```
Спрайты собираются в пул и повторно используются в разных подсказках вместо того, чтобы создаваться заново; устаревшие буллеты скрываются с помощью непрозрачности `0`. Буллеты выравниваются по вертикали по высоте поля ввода.

`display_normal_callback()` — это обратное действие: оно восстанавливает непрозрачность `1.0`, скрывает подсказку, поле ввода и каждый пуловый буллет. Зарегистрировано с `PlymouthSetDisplayNormalFunction`, Plymouth вызывает это, когда пароль принят или отменен, и загрузка продолжается.

Следствие: `logo.opacity` — это переменная, а не константа, потому что как затухание, так и состояние пароля умножаются на неё.

### 6. Появление

```js
Plymouth.SetRefreshRate(20);
fun refresh_callback()
{
    if (!fade.complete) {
        fade.frame += 1;
        fade.opacity = fade.frame / 20;      /* 20 frames @ 20 FPS = 1s */
        if (fade.opacity > 1) fade.opacity = 1;
        text.sprite.SetOpacity(fade.opacity);
        progress_track.sprite.SetOpacity(fade.opacity);
        progress_bar.sprite.SetOpacity(fade.opacity);
        if (fade.frame >= 20) fade.complete = 1;
    }
    logo.sprite.SetOpacity(logo.opacity * fade.opacity);
}
```
Обратная функция обновления продолжает работать на протяжении всей загрузки (это дешево, и Plymouth вызывает её непрерывно); защита `fade.complete` делает её пустой операцией после анимации. Логотип использует `logo.opacity * fade.opacity` вместо простого присвоения, чтобы затемнённое паролем состояние сохранялось после затухания: после завершения затухания `fade.opacity == 1` и логотип снова показывает `logo.opacity`.

Ранние версии этой темы также имели анимации пульса/создания; они были удалены в `0.2.0` ("chore: remove pulse effects"). Не вводите обратно покадровую анимацию индикатора прогресса — индикатор должен оставаться точным отображением процесса загрузки.

## Константы расположения

Единый источник правды для настройки композиции:

| Константа | Значение | Значение |
| --- | --- | --- |
| `logo.base_scale` | `0.72` | масштаб логотипа относительно его исходного 256x256 |
| `logo.y` смещение | `-35` | поднимает центрированный блок выше середины экрана |
| `text.scale` | `0.80` | масштаб словесного знака относительно его исходного 400x53 |
| `text.y` зазор | `+16` | нижняя часть логотипа → верхняя часть словесного знака |
| `progress_track.y` зазор | `+28` | нижняя часть словесного знака → верхняя часть дорожки |
| `password.prompt.y` зазор | `+24` | нижняя часть дорожки → верх текста подсказки |
| `password.entry.y` зазор | `+14` | нижняя часть подсказки → верх поля ввода |
| смещение x маркера | `+16` | левый край поля ввода → первый маркер |
| `logo.opacity` (диалог) | `0.15` | затемнение заставки во время запроса пароля |
| цвет подсказки | `0.72, 0.77, 0.81` | `Image.Text` RGB, ~`#B8C4CE` |
| затемнение | 20 кадров @ 20 FPS | ~1 секунда появления |

## Дизайнерские токены

| Токен | Hex | Где находится |
| --- | --- | --- |
| Фон | `#111316` | скрипт (`0.0667, 0.0745, 0.0863`) |
| Акцент | `#3590BD` | логотип / фирменное название / пиксели заполнения прогресса |
| Трек прогресса | `#262933` | `progress-bar-track.png` |
| Текст запроса | `#B8C4CE` | скрипт (вызов `Image.Text`) |

Цвета акцента и трека зашиты в PNG-ресурсах и не заданы в скрипте, поэтому изменение цвета требует повторного экспорта ресурсов (или редактирования палитры). Тема только темная и не имеет светлого варианта.

## Формат растрового изображения UKI

`argvus-uki-splash.bmp` — это 400x400, 32-битный несжатый Windows BMP (`PC bitmap, Windows 98/2000 and newer format, 400 x 400 x 32`). Это самостоятельный ресурс: скрипт Plymouth его не загружает, и пакет Arch нигде его не регистрирует — внедрение в UKI осуществляется пользователем (см. [руководство пользователя](/docs/argvus-boot-splash/uki-splash/)]).

Если вы замените его, используйте простой несжатый 32-битный BMP сопоставимого размера; systemd-boot и `ukify` не масштабируют произвольные форматы, а большие изображения потребляют много памяти на ранней стадии загрузки.

## Изменение темы

Практический цикл:

1. Редактируйте `src/usr/share/plymouth/themes/argvus/argvus.script` (и/или PNG).
2. Установите в ваш live Plymouth или предварительно просмотрите из исходного дерева:

   ```sh
   sudo cp -r src/usr/share/plymouth/themes/argvus/* \
              /usr/share/plymouth/themes/argvus/
   sudo plymouth-set-default-theme argvus
   sudo plymouth --show-splash    # check, then: sudo plymouthquit
   ```
3. `make validate && make build` перед коммитом.

Правила, которые поддерживают работу темы:

- Никогда не используйте API, не относящиеся к Plymouth. Движок использует ограниченный диалект; проверьте целевую версию `plymouth`, которую вы поддерживаете, перед использованием API, с которым вы раньше не работали.
- `ImageDir`/`ScriptFile` в `argvus.plymouth` должны оставаться абсолютными и соответствовать установленному пути `/usr/share/plymouth/themes/argvus`.
- Поддерживайте синхронизацию всех ресурсов, перечисленных в `arch_check_splash_payload()`, с файлами, которые поставляются в `src/` — упаковка `check()` выполняется в CI.
- Ширина индикатора прогресса должна оставаться точной функцией от сообщаемого прогресса; ограничение до `[1, track width]` не должно быть удалено.
- Тестируйте диалог ввода пароля, а не только стартовый экран: это состояние наиболее склонно к сбоям и на которое пользователи обращают больше всего внимания.
- Колбэк обновления выполняется на протяжении всей загрузки; освобождайте выделение работы на каждый кадр, где это возможно.
