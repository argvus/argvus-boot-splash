# トラブルシューティング

**インストール後にスプラッシュが変わらない。**
initramfs が再生成されていません。`sudo mkinitcpio -P`（または `sudo dracut --regenerate-all`）を実行して再起動してください。システムが複数のカーネルを使用している場合、起動するカーネルが新しい initramfs を使っていることを確認してください。

**スプラッシュが全く表示されない；画面が黒いかテキストのみ。**
`plymouth` が initramfs フックに存在しません。`/etc/mkinitcpio.conf` を確認し、`HOOKS=(...)` に `plymouth` が含まれていることを確認してから再構築し再起動してください。Ubuntu/Debian では、`plymouth` および `plymouth-x11`/`plymouth-themes` がインストールされており、`GRUB_CMDLINE_LINUX` に `splash quiet` が存在することも確認してください。

**ロゴのみで進行状況が表示されない。**
init が一部の起動ステップを報告しない場合、または進行状況コールバックが一度も呼ばれない場合でも、あなたの側で何かが壊れているわけではありません。バーは Plymouth によって報告された進行状況で埋まりますが、いくつかの設定（例えば systemd の `plymouth-spawn` 非対応のシーケンスや特定の dracut モジュール）では進行状況が存在しません。

**パスワードプロンプトが誤った位置にある、または見えません。**  
ダイアログはロゴとトラックジオメトリから位置が決まるため、極端な解像度（非常に小さいテキストモード）では画面外に押し出されることがあります。通常の解像度を使用し、一般的な解像度でも発生する場合は報告してください。  

**Plymouthが早期に終了する / テキストコンソールが表示される。**  
Plymouthを無効にした原因としては、`quiet`が設定され`splash`がないブートパラメータ、`plymouth`フックが削除された、またはPlymouthが使用できないドライバーがあります。Plymouthはマシンをフリーズさせる代わりにテキストコンソールに終了します — これは予期された動作です。  

**`argvus-plymouth`からアップグレード後にテーマが適用されない。**  
新しいパッケージが古いものを置き換えます。`/etc/plymouth/plymouthd.conf`が`PLYMOUTH_THEME_NAME=argvus`であることを確認し、initramfsを再構築してください。  

**署名確認中にインストールが失敗する。**  
リポジトリキーがキーリングに存在しないか、期限切れです。現在の公開鍵を再インポートし、その後`sudo pacman -Sy`を行ってください。

**ロック画面 / サスペンドは変更されていません。**  
テーマは起動時のみ適用されます。ハイバネート / レジューム画面は別に制御されます  
(`systemd-homed`、スクリーンロッカー、initramfs のスリープターゲットでの `plymouth` の使用)。

**プレビュー後も Plymouth が残って実行されています。**  
`sudo plymouthquit` がセッションを復元します。画面が黒いままの場合は、別の仮想端末に切り替えてください (`Ctrl+Alt+F2`) — セッションはそのままです。
